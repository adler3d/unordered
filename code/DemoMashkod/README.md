# 🧪 DemoMashkod

> *"Не пиши на C++. Пиши на том, что *становится* C++."*

Этот репозиторий — **не игра, не движок, не фреймворк**.  
Это — **система трансляции**, где код проходит через несколько слоёв, превращаясь из C++-подобного синтаксиса в исполняемый байткод.

**`DemoMashkod`** — это **экспериментальная платформа** для построения **скриптовых систем**, **встроенных DSL**, **мета-программирования** и **ручного управления памятью и кодом**.

---

## 🔗 Архитектура: от `cpplike` до `mashkod`

Вся система построена как **двухэтапная трансляция**:

```text
[1] C++-подобный код
     ↓
[V2/Sgon.exe] → парсит и генерирует AsmCppLike
     ↓
qapcppout.asm
     ↓
копируется в → asm2mashkod2016.h
     ↓
[AsmCppLike2Mashkod/Sgon.exe] → парсит AsmCppLike, генерирует mashkod.asm
     ↓
mashkod.txt
     ↓
[ASM_APP.exe] → загружает и исполняет
```

### 🔹 Этап 1: `C++ → AsmCppLike`
- Используется: `321/V2/Sgon.exe`
- Вход: `test2016.h` (C++-подобный синтаксис)
- Выход: `qapcppout.asm` (текст на AsmCppLike)

### 🔹 Этап 2: `AsmCppLike → Mashkod`
- Используется: `321/AsmCppLike2Mashkod/Sgon.exe`
- Вход: `asm2mashkod2016.h` (содержит `qapcppout.asm`)
- Выход: `mashkod.asm` → `mashkod.txt` (финальный байткод)

### 🔹 Этап 3: Исполнение
- `ASM_APP.exe` загружает `mashkod.txt` и исполняет его.
- Используются: `QapProgramD3D9.inl`, `OutDeviceEx.inl`, `t_dev`, `t_input`.

## 🛠️ Как собрать и запустить

### 1. Запуск пайплайна
```bat
CL_APP&RUN(QapPipelineO2).bat
```

Этот скрипт:
1. Запускает `V2/Sgon.exe` → генерирует `qapcppout.asm`.
2. Копирует его в `AsmCppLike2Mashkod/Release/asm2mashkod2016.h`.
3. Запускает `AsmCppLike2Mashkod/Sgon.exe` → генерирует `mashkod.asm`.
4. Копирует `mashkod.asm` в `Release/mashkod.txt`.
5. Запускает `ASM_APP.bat`.

### 2. Результат
- `mashkod.txt` — финальный байткод.
- `ASM_APP.exe` — загружает и исполняет его.

## 💡 Ключевые идеи

### 1. **Два разных проекта с именем `Sgon`**
- Это **не один и тот же `.exe`**, запущенный дважды.
- Это **два разных проекта**, созданных по шаблону.
- Оба называются `Sgon.exe` для удобства (не нужно настраивать VCXPROJ заново).

### 2. **AsmCppLike — это промежуточный текстовый IR**
- Не байткод, не C++.
- Это **ассемблероподобный язык**, сгенерированный из AST.
- Пример:
  ```asm
  proc("func_new_geom(int)")
    PARAM_RESULT("t_out_dev")
    PARAM("int", param_n)
    VAR("t_out_dev", var_tmp)
    lea(ecx, var_tmp)
    call("func_t_out_dev::`ctor()")
    mov(ebx, 255); shl(ebx, 24); mov(var_tmp["color"], ebx)
    ...
    ret()
  ```

### 3. **Mashkod — это финальный исполняемый формат**
- `mashkod.txt` — результат трансляции.
- Загружается `ASM_APP.exe` и исполняется.
- Может содержать данные, функции, структуры, вызовы.

### 4. **Всё под контролем**
- Нет `std::vector`, `new`, `malloc` — только `alloc`, `get_int`, `set_int`.
- Нет внешних зависимостей — всё в `.inl`, всё в памяти.
- Ассемблер вставляется через `__asm(...)`, но это — **MashkodASM**, не x86.

---

## 🧰 Используемые технологии

- **C++ с инлайн-ассемблером** (`__asm(...)`) — для низкоуровневого контроля.
- **Рефлексия через `IEnvRTTI`** — для динамического создания и анализа типов.
- **Собственные контейнеры** (`vector_qap_vertex`, `vector_int`) — без STL.
- **Сериализация вручную** (`t_dev`, `write`, `read`) — через `rep_movsd_inc()`.
- **Генерация кода** — на основе AST и грамматик в `.inl`.

## ❓ Почему так?

- **Почему два `Sgon.exe`?**  
  Потому что это **два разных проекта**, созданных копированием для удобства. Нет смысла настраивать VCXPROJ заново.

- **Почему `.asm`?**  
  Это **не x86 ассемблер**, а **текстовое представление IR** (AsmCppLike). Расширение `.asm` — для удобства.

- **Почему `mashkod.txt`?**  
  Это **сериализованный байткод**, который можно легко загрузить в `ASM_APP.exe`.
